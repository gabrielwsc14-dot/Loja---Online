🌐 Como Publicar QUALQUER Site HTML no GitHub Pages

Guia visual completo e prático para hospedar sites gratuitamente no GitHub

✅ O que você vai aprender

  • Como publicar qualquer pasta HTML gratuitamente
  • 3 métodos diferentes de publicação (raiz, /docs, gh-pages)
  • Resolver problemas comuns (404, CSS não carrega, etc.)
  • Atualizar seu site automaticamente
  • Usar domínio personalizado (opcional)

📋 Pré-requisitos

  • ✅ Ter uma conta no GitHub (gratuita)
  • ✅ Seu site em HTML, CSS e JavaScript
  • ✅ Um arquivo index.html (obrigatório!)
  • ✅ Repositório público (GitHub Pages é grátis só para públicos)
💡 Não sabe usar Git? Você pode fazer tudo pela interface web do GitHub!

🎯 Escolha o Método de Publicação

Método 1: Raiz do Repositório (/ root) - MAIS COMUM

Use quando: Seus arquivos HTML estão na pasta principal

Estrutura:

seu-repositorio/
├── index.html  ← Arquivo principal
├── style.css
├── script.js
└── imagens/

Método 2: Pasta /docs - RECOMENDADO

Use quando: Quer separar código-fonte da versão publicada

Estrutura:

seu-repositorio/
├── src/         ← Código fonte
└── docs/        ← Site para publicar
    ├── index.html
    ├── style.css
    └── imagens/

Método 3: Branch gh-pages - AVANÇADO

Use quando: Quer manter código e site 100% separados

💡 Neste guia, vamos usar o Método 1 (raiz). Os outros métodos são similares.

1 Prepare Seus Arquivos

✅ Checklist Obrigatória:

  • Arquivo index.html: Deve existir e ter exatamente este nome
  • Caminhos relativos: Use href="style.css" não href="/style.css"
  • Nomes minúsculos: Use sobre.html não Sobre.html
  • Sem espaços: Use minha-foto.jpg não minha foto.jpg

Exemplo de HTML correto:

<!-- ✅ CORRETO -->
<link rel="stylesheet" href="style.css">
<img src="imagens/logo.png">
<a href="sobre.html">Sobre</a>

<!-- ❌ ERRADO -->
<link rel="stylesheet" href="/style.css">  ← Barra no início
<img src="C:/site/imagens/logo.png">  ← Caminho absoluto

2 Envie para o GitHub

Opção A: Usando a Interface Web (Mais Fácil)

  1. Acesse github.com/new e crie um repositório
  2. Clique em uploading an existing file
  3. Arraste todos os seus arquivos HTML, CSS, JS e imagens
  4. Clique em Commit changes

Opção B: Usando Git (Terminal)

# Na pasta do seu site:
git init
git add .
git commit -m "Primeiro commit"
git branch -M main
git remote add origin https://github.com/SEU-USUARIO/SEU-REPO.git
git push -u origin main

3 Ative o GitHub Pages

  1. No seu repositório, clique em Settings (topo da página)
  2. No menu lateral esquerdo, clique em Pages
  3. Em Source, selecione:
    • Branch: main
    • Folder: / (root) ou /docs (conforme seu método)
  4. Clique em Save
💡 Se não ver o branch "main", verifique se é "master" na aba Code.

4 Aguarde a Publicação

Após salvar:

  • ⏱️ Primeira vez: 2 a 10 minutos
  • 🔄 Atualizações: 30 segundos a 5 minutos
  • 📧 Você receberá um email quando estiver pronto
  • ✅ Um banner verde aparecerá com o link do seu site

5 Acesse Seu Site!

Seu site estará disponível em:

https://SEU-USUARIO.github.io/NOME-DO-REPOSITORIO/

Exemplo real:

https://joaosilva.github.io/meu-portfolio/

✅ Compartilhe este link com qualquer pessoa!

✅ Funciona em qualquer dispositivo (PC, celular, tablet)

✅ HTTPS automático (seguro com cadeado 🔒)

🔄 Como Atualizar Seu Site

Depois de publicado, qualquer alteração é atualizada automaticamente!

Opção A: Interface Web do GitHub

  1. No repositório, clique no arquivo que quer editar
  2. Clique no ícone de lápis ✏️ (Edit)
  3. Faça suas alterações
  4. Role para baixo e clique em Commit changes
  5. Aguarde 1-5 minutos → Site atualizado! 🎉

Opção B: Terminal/Git

# 1. Edite seus arquivos HTML/CSS/JS

# 2. Adicione as mudanças
git add .

# 3. Faça um commit
git commit -m "Atualizei o menu principal"

# 4. Envie para o GitHub
git push origin main

# 5. Aguarde 1-5 minutos → Site atualizado! 🎉
💡 Limpe o cache do navegador (Ctrl+Shift+R) se não ver as mudanças.

📁 Arquivo .nojekyll (Importante!)

Se seu site tem pastas ou arquivos que começam com _ (underscore), crie um arquivo vazio chamado .nojekyll na raiz:

Por que fazer isso?

O GitHub Pages usa Jekyll por padrão, que ignora pastas como _css, _js, _imagens. O arquivo .nojekyll desativa isso.

Como criar (Interface Web):

  1. No repositório, clique em Add file → Create new file
  2. Nome do arquivo: .nojekyll
  3. Deixe em branco (arquivo vazio)
  4. Clique em Commit new file

Como criar (Terminal):

touch .nojekyll
git add .nojekyll
git commit -m "Add .nojekyll"
git push

⚠️ Observações Importantes

Requisitos Obrigatórios:

  • ✅ Repositório Público: GitHub Pages grátis só para públicos
  • ✅ index.html: Arquivo principal DEVE ter este nome exato
  • ✅ Caminhos Relativos: Nunca use / no início dos caminhos
  • ✅ Minúsculas: Nomes de arquivos em minúsculas (case-sensitive)
  • ✅ Sem Espaços: Use - ou _ ao invés de espaços

O que GitHub Pages NÃO suporta:

  • ❌ PHP, Python, Ruby (linguagens de backend)
  • ❌ Banco de dados (MySQL, PostgreSQL)
  • ❌ Upload de arquivos pelo usuário
  • ❌ APIs privadas (mas pode chamar APIs públicas externas)

O que você PODE fazer:

  • ✅ HTML, CSS, JavaScript
  • ✅ Frameworks JavaScript (React, Vue, Angular compilados)
  • ✅ Integrar APIs externas (Stripe, PayPal, Firebase, etc.)
  • ✅ LocalStorage e SessionStorage

🎯 Domínio Personalizado (Opcional)

Quer usar seu próprio domínio? (ex: www.seusite.com.br)

Passo 1: Compre um Domínio

Registradores populares no Brasil:

  • Registro.br - Domínios .br (mais barato)
  • GoDaddy - Internacional
  • HostGator - Brasil
  • Namecheap - Internacional (barato)

Passo 2: Configure no GitHub

  1. Em Settings > Pages
  2. Na seção Custom domain, digite seu domínio
  3. Clique em Save
  4. Marque Enforce HTTPS (pode demorar algumas horas)

Passo 3: Configure DNS no Registrador

No painel do seu registrador de domínio, adicione estes registros:

Para domínio raiz (seusite.com.br):

Tipo A - IP 185.199.108.153
Tipo A - IP 185.199.109.153
Tipo A - IP 185.199.110.153
Tipo A - IP 185.199.111.153

Para subdomínio www (www.seusite.com.br):

Tipo CNAME - Valor: SEU-USUARIO.github.io

Passo 4: Aguarde

DNS pode levar de 1 hora a 48 horas para propagar. Teste em: dnschecker.org

💡 Esta etapa é 100% opcional. Seu site funciona perfeitamente com o endereço github.io gratuito!

❓ Problemas Comuns e Soluções

🔴 Problema 1: Site não aparece / Erro 404

Sintomas: Ao acessar o link, aparece "404 - File not found"

Soluções:

  • ✅ Verifique o arquivo index.html: Deve estar na pasta raiz (ou /docs se escolheu este método)
  • ✅ Aguarde: Primeira publicação pode levar até 10 minutos
  • ✅ Repositório público: Vá em Settings > General e verifique se não está "Private"
  • ✅ Branch correto: Em Settings > Pages, confirme que selecionou o branch certo
  • ✅ Limpe o cache: Pressione Ctrl+Shift+R (Windows) ou Cmd+Shift+R (Mac)

🔴 Problema 2: CSS e JavaScript não carregam

Sintomas: Site aparece, mas sem estilos ou funcionalidades

Soluções:

  • ✅ Caminhos relativos: Use href="style.css" NÃO href="/style.css"
  • ✅ Arquivo .nojekyll: Crie se usa pastas com _ (underscore)
  • ✅ Verifique nomes: CSS/JS devem ter nomes em minúsculas
  • ✅ Console do navegador: Pressione F12 e veja erros na aba Console

Exemplo correto vs incorreto:

✅ CORRETO:
<link rel="stylesheet" href="css/style.css">
<script src="js/script.js"></script>

❌ ERRADO:
<link rel="stylesheet" href="/css/style.css">  ← Barra no início
<script src="C:/site/js/script.js"></script>  ← Caminho absoluto

🔴 Problema 3: Imagens não aparecem

Sintomas: Ícone de imagem quebrada 🖼️❌

Soluções:

  • ✅ Arquivos no repositório: Confirme que as imagens foram enviadas
  • ✅ Caminhos corretos: Use src="imagens/logo.png"
  • ✅ Extensões minúsculas: Use .jpg não .JPG
  • ✅ Nomes sem espaços: minha-foto.jpg não minha foto.jpg

🔴 Problema 4: Mudanças não aparecem

Sintomas: Fiz alterações mas o site continua antigo

Soluções:

  • ✅ Aguarde: Pode demorar até 5 minutos para atualizar
  • ✅ Verifique o commit: Confirme que fez push para o GitHub
  • ✅ Limpe cache: Ctrl+Shift+R ou abra em modo anônimo
  • ✅ Verifique status: Em Settings > Pages, veja se há erros

🔴 Problema 5: Links quebrados entre páginas

Sintomas: Ao clicar em links internos, aparece 404

Soluções:

  • ✅ Use nomes exatos: sobre.html não Sobre.html
  • ✅ Caminhos relativos: <a href="contato.html">
  • ✅ Arquivos existem: Confirme que as páginas estão no repositório

🔴 Problema 6: "Build" falhou

Sintomas: Email dizendo que o build falhou

Soluções:

  • ✅ Verifique Actions: Aba "Actions" no repositório mostra o erro
  • ✅ Arquivo .nojekyll: Adicione se não tiver
  • ✅ Sintaxe HTML: Use validador em validator.w3.org

❓ Perguntas Frequentes

É realmente grátis?

✅ Sim! 100% gratuito para repositórios públicos, sem custo escondido.

Posso usar PHP, MySQL, banco de dados?

❌ Não. GitHub Pages só suporta sites estáticos (HTML/CSS/JS). Para backend, use:

  • • Netlify ou Vercel (para sites dinâmicos)
  • • Firebase (para banco de dados NoSQL)
  • • Heroku ou Railway (para backend completo)

Quantos sites posso ter?

✅ Ilimitados! Um site por repositório, sem limite de repositórios.

Posso vender produtos online?

✅ Sim, integrando com APIs de pagamento:

  • • Stripe, PayPal, Mercado Pago
  • • PagSeguro, Cielo

Tem limite de visitantes?

⚠️ Limites do GitHub Pages:

  • • 100 GB de banda por mês
  • • 1 GB de espaço total
  • • 10 builds por hora

Suficiente para a maioria dos sites pequenos e médios.

Meu site vai sair do ar?

✅ Não! Uma vez publicado, fica online indefinidamente (enquanto o repositório existir).

Posso usar React, Vue, Angular?

✅ Sim! Mas você precisa compilar primeiro (npm run build) e publicar a pasta dist/ ou build/.
